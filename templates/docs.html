API reference

Humanizer API

Rewrite text programmatically with the same engine as the editor. One endpoint, JSON in and JSON out.

Base URL {{ base_url }}
{{ icon('shield') }} API key auth Send your key in the X-API-Key header.
{{ icon('zap') }} One endpoint POST /humanize returns the result instantly.
{{ icon('file') }} 20,000 characters Maximum text length per request.

Authentication

Every request needs an API key. Create one on the Dashboard and send it in the X-API-Key header.

Header
X-API-Key: hmnz_your_api_key_here
{{ icon('alert') }}Treat your key like a password. Keep it out of client-side code and version control. Keys are shown only once, so store them in a secrets manager or environment variable.

Plans & quota

Plans cover 30 days, or a year at the price of 10 months; buying again while a plan is active adds the new period and carries over unused requests. See Pricing for the price in your region.

Top-ups add requests that never expire. Each request uses your plan's requests first and top-up requests only after those run out (or once the plan ends), so a top-up also works on its own, without a plan.

Every successful response includes what's left, so you can warn users before it runs out. Only valid requests count: requests rejected with a 4xx error or failing on our side are not charged. We also email you when 80% is used.

When the plan's requests and top-up requests are both used up, the API answers with 402 Payment Required and a link to the pricing page. The web editor is free and never uses API quota.

Endpoint

Rewrites the submitted text and returns the result with change statistics.

POST{{ base_url }}humanize

Request

Headers

HeaderValue
Content-Typeapplication/jsonRequired
X-API-KeyYour API keyRequired

Body parameters

ParameterDescription
text
string		 The text to humanize. Up to 20,000 characters. Required
tone
string		 "standard", "professional", "casual" or "academic". Casual uses contractions, shorter words and splits long sentences; professional and academic expand contractions, and academic keeps a formal vocabulary. Default: "standard". Optional
deep_mode
boolean		 Chaos Mode: a deeper rewrite that swaps far more words and splits long compound sentences. Default: false. Optional

Example body

JSON 
{
  "text": "The quick brown fox jumps over the lazy dog.",
  "tone": "professional",
  "deep_mode": true
}

Response

A successful request returns 200 OK with this JSON body.

200 OK 
{
  "original": "The quick brown fox jumps over the lazy dog.",
  "humanized": "The speedy brown fox jumps over the lazy dog.",
  "diff_html": "<span class=\"unchanged\">The</span> <span class=\"added\">speedy</span> ...",
  "longest_unchanged": "brown fox jumps over the lazy dog.",
  "structural_changes": "11.1%",
  "changed_words": 1
}

Fields

FieldDescription
original
string		The text you sent.
humanized
string		The rewritten text, with line breaks preserved.
diff_html
string		HTML-escaped output with each word wrapped in a span of class added (changed) or unchanged.
longest_unchanged
string		The longest run of words left exactly as in the input, or "None".
structural_changes
string		How different the word sequence is, as a percentage.
changed_words
integer		Number of words that were rewritten.

Batch requests

Rewrite up to 25 texts in one call. Each item uses one request from your quota, so a batch costs the same as sending the items one by one, with a single round trip. Items that fail on our side are not charged.

POST{{ base_url }}humanize/batch

Send items: a list of strings, or of objects with text and optional tone, deep_mode and id (echoed back, up to 100 characters). Top-level tone and deep_mode set the defaults. Batch requests need an API key.

Request body
{
  "tone": "professional",
  "items": [
    "First paragraph to rewrite.",
    {"id": "faq-2", "text": "Second paragraph.", "tone": "casual"}
  ]
}

Results come back in the same order. Each has the item's index (and id if you sent one), plus either the rewrite (humanized, longest_unchanged, structural_changes, changed_words) or an error. The diff HTML is left out to keep responses small.

200 OK
{
  "count": 2,
  "succeeded": 2,
  "processing_ms": 412.5,
  "results": [
    {"index": 0, "humanized": "…", "longest_unchanged": "…", "structural_changes": "71%", "changed_words": 3},
    {"index": 1, "id": "faq-2", "humanized": "…", "longest_unchanged": "None", "structural_changes": "100%", "changed_words": 2}
  ]
}

A batch is checked as a whole before anything is charged: if any item is invalid, the response is a 400 naming the item (for example Item 3: text too long) and nothing is used. Limits: 25 items and 50,000 characters per batch, each item up to 20,000 characters. Each item counts toward the per-key rate limit.

Code examples

Replace hmnz_your_api_key_here with a key from your dashboard.

curl -X POST {{ base_url }}humanize \
  -H "Content-Type: application/json" \
  -H "X-API-Key: hmnz_your_api_key_here" \
  -d '{
    "text": "Your AI-generated text here",
    "tone": "professional",
    "deep_mode": true
  }'
import requests

url = "{{ base_url }}humanize"
headers = {
    "Content-Type": "application/json",
    "X-API-Key": "hmnz_your_api_key_here"
}
payload = {
    "text": "Your AI-generated text here",
    "tone": "professional",
    "deep_mode": True
}

response = requests.post(url, json=payload, headers=headers)
data = response.json()

print(f"Humanized: {data['humanized']}")
print(f"Changed words: {data['changed_words']}")
const response = await fetch('{{ base_url }}humanize', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    'X-API-Key': 'hmnz_your_api_key_here'
  },
  body: JSON.stringify({
    text: 'Your AI-generated text here',
    tone: 'professional',
    deep_mode: true
  })
});

const data = await response.json();
console.log('Humanized:', data.humanized);
console.log('Changed words:', data.changed_words);
<?php
$url = '{{ base_url }}humanize';
$data = array(
    'text' => 'Your AI-generated text here',
    'tone' => 'professional',
    'deep_mode' => true
);

$options = array(
    'http' => array(
        'header'  => "Content-type: application/json\r\n" .
                     "X-API-Key: hmnz_your_api_key_here\r\n",
        'method'  => 'POST',
        'content' => json_encode($data)
    )
);

$context  = stream_context_create($options);
$result = file_get_contents($url, false, $context);
$response = json_decode($result);

echo "Humanized: " . $response->humanized . "\n";
echo "Changed words: " . $response->changed_words . "\n";
?>
